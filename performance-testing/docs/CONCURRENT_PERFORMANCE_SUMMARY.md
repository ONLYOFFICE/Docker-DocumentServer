# 📊 ONLYOFFICE Document Server 并发性能分析 - 完整总结

## 核心发现

### 理论并发上限

**ONLYOFFICE Document Server 的并发能力由以下因素共同决定**：

```
┌─────────────────────────────────────────────────────────────┐
│  实际并发上限 = min(                                        │
│    ① 文件描述符限制（FD）                                  │
│    ② Nginx 连接数（Worker进程 × 单Worker连接数）          │
│    ③ 数据库连接数（max_connections - 预留）               │
│    ④ 内存支持（可用内存 / 人均占用）                      │
│    ⑤ CPU 处理能力                                         │
│  )                                                        │
└─────────────────────────────────────────────────────────────┘
```

### 主要瓶颈（通常情况）

| 级别 | 瓶颈 | 默认值 | 优化后 | 优先级 |
|------|------|--------|--------|--------|
| 1️⃣ | 数据库连接 | 100 | 200-500 | ⭐⭐⭐ 最关键 |
| 2️⃣ | 文件描述符 | 1024 | 65536+ | ⭐⭐⭐ 必须 |
| 3️⃣ | Nginx Workers | 1 | CPU核数 | ⭐⭐ 重要 |
| 4️⃣ | 内存 | 4GB | 16GB+ | ⭐⭐ 重要 |

## 快速优化建议（立即实施）

### 🔥 必须做的 3 件事

#### 1. 调整文件描述符限制
**为什么**：系统默认只允许 1024 个 FD，远远不够
**如何做**：
```bash
# 临时（当前会话）
ulimit -n 131072

# 永久（宿主机）
echo "* soft nofile 131072" | sudo tee -a /etc/security/limits.conf
echo "* hard nofile 1048576" | sudo tee -a /etc/security/limits.conf
```
**效果**：并发能力可提升 10 倍

#### 2. 优化 Nginx Worker 配置
**为什么**：默认只有 1 个 worker，不能充分利用多核 CPU
**如何做**：
```bash
docker run -d \
  -e NGINX_WORKER_PROCESSES=8      # 等于 CPU 核心数
  -e NGINX_WORKER_CONNECTIONS=32768 # 每个 worker 的最大连接
  onlyoffice/documentserver
```
**效果**：并发能力提升 8 倍（对于 8 核 CPU）

#### 3. 增加数据库连接数
**为什么**：数据库连接是最常见的瓶颈
**如何做**：
```bash
# 在 PostgreSQL 中
ALTER SYSTEM SET max_connections = 200;
SELECT pg_reload_conf();
```
**效果**：并发能力从 ~20 提升到 ~100+

## 常见问题解答

### Q1：我现在的并发数只有 20，如何扩展到 100？
**A**：需要同时调整多个参数：
1. **增加硬件**：4C4G → 8C16G
2. **调整系统**：ulimit -n 65536
3. **优化配置**：NGINX_WORKER_PROCESSES=8
4. **扩展数据库**：max_connections 从 100 增加到 200
5. **外部化服务**：数据库和缓存不在容器内

### Q2：如何判断是否需要升级？
**A**：满足以下任一条件时应该升级：
- CPU 持续使用率 > 85%
- 内存使用率 > 90%
- P95 响应时间 > 800ms
- 数据库连接接近上限

### Q3：单机最多能支持多少并发？
**A**：取决于硬件配置：
- 4 核 4GB → ~50 用户
- 8 核 16GB → ~150 用户
- 16 核 32GB → ~450 用户
- 超过 500 用户需要多机部署

### Q4：为什么响应时间会随着并发数增加而快速变慢？
**A**：可能的原因：
1. 数据库连接耗尽（最常见）
2. CPU 利用率接近 100%
3. 磁盘 I/O 成为瓶颈
4. 内存不足导致频繁交换
