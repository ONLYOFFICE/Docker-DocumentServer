## 🎯 核心发现（一句话总结）

### 理论并发上限的计算公式
```
实际并发 = min(
  ① 文件描述符限制,
  ② Nginx Worker 连接数,
  ③ 数据库连接数,  ← 通常是瓶颈
  ④ 内存容量支持
)
```

### 不同硬件的性能表现

| 配置 | 并发用户 | 吞吐量 | 成本/年 | 推荐度 |
|------|---------|--------|---------|--------|
| **2C2G** | 10-20 | 50-100 RPS | ¥600 | ⭐ 测试用 |
| **4C4G** | 30-50 | 150-250 RPS | ¥1,200 | ⭐⭐⭐⭐⭐ |
| **8C16G** | 100-180 | 300-500 RPS | ¥3,600 | ⭐⭐⭐⭐⭐ |
| **16C32G** | 300-450 | 600-1000 RPS | ¥10,800 | ⭐⭐⭐⭐ |

### 最重要的 3 个优化

1. **增加文件描述符** `ulimit -n 131072` → 提升 60 倍
2. **设置 Worker 进程** `NGINX_WORKER_PROCESSES=CPU核数` → 提升 8 倍
3. **增加 DB 连接数** `max_connections = 200` → 提升 2 倍

## 💡 您最常问的 3 个问题

### Q1：我的 50 人团队应该买什么配置？
**A**：`4 核 4GB` 内存的服务器（约 ¥1,200/年）
- 支持 30-50 并发用户
- 性价比最优
- 推荐小型到中型企业

### Q2：为什么我现在只能支持 20 个并发？
**A**：最可能的原因（按优先级）：
1. 文件描述符限制（默认 1024）
2. 数据库连接不足（默认 100）
3. Nginx Worker 进程数过少（默认 1）

**解决**：运行 `./performance-diagnosis.sh` 可获得准确答案

### Q3：如何支持 500 个并发用户？
**A**：需要多个条件同时满足：
- 硬件：16 核 32GB 内存
- 架构：多机部署 + 负载均衡
- 成本：¥10,800+/年
- 维护：需要专业运维团队
